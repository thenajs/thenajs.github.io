Report de execução

Com report: true no config, ao final da run o ThenaJS escreve um relatório (HTML + JSON) em report/ — estilo Playwright.

config.ts
export const config: ThenaConfig = {
  report: true, // ou { dir: "report", format: "html" | "json" | "both" }
};

O que ele mostra

A árvore da execução — workflow → loop / parallel → agent → chat → tool — com durações, status e o conteúdo de cada passo (o que foi enviado ao modelo, a resposta, a decisão de tool e o I/O das tools). É como você mede o nível da aplicação: onde o tempo foi gasto, quais decisões o modelo tomou e onde houve erro.

O que dá para medir sem regex

Além de duração e status, cada nó carrega metadados estruturados em data — a ideia é que medir uma execução não exija parsear o texto de saída.

NóCampos em data
workflowchatCalls, toolCalls, tokens, costUsd, elapsedMs, exceeded
loopiterations, exhausted, maxIterations
chattoolCallSource, promptTokens, completionTokens, costUsd
toolisError (e status: "error" no nó)

Ou seja: tool_error_rate é contar nós kind: "tool" com status: "error"; a taxa de resgate é contar toolCallSource === "rescued"; e loops que não convergiram são exhausted: true.

Como funciona por dentro

Uma camada de interceptação leve (um recorder com AsyncLocalStorage) monta a árvore conforme a execução acontece — o parentesco fica correto mesmo em parallel. Ao final, a árvore é serializada num HTML autocontido (colapsável via <details>, sem JavaScript) e num JSON.

Opt-in, zero custo quando desligado

Sem report, nada é gerado e não há overhead — o recorder é no-op. Não há serviço externo nem telemetria: o report é só um arquivo local. Ligue em dev/CI para depurar; deixe desligado em produção.
