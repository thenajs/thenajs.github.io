Providers

O provider é quem conversa com o modelo. O engine traz OllamaProvider e OpenAIProvider; o padrão é criar uma subclasse com as credenciais já configuradas.

providers/ollama.provider.ts
import { OllamaProvider } from "@thenajs/core";

export class LocalOllamaProvider extends OllamaProvider {
  constructor() {
    super({ host: "http://localhost:11434", model: "qwen2.5-coder:7b" });
  }
}

O agente referencia a classe do provider (ou uma instância). Assim as credenciais ficam num lugar só, fora dos agentes.

Parâmetros de amostragem

sampling é um shape neutro que cada provider traduz para as chaves nativas. Nada tem default: o que você não informar não é enviado, e o modelo mantém o comportamento dele. Para iterar determinismo, o par temperature: 0 + seed é o ponto de partida.

providers/ollama.provider.ts
export class LocalOllamaProvider extends OllamaProvider {
  constructor() {
    super({
      host: "http://localhost:11434",
      model: "qwen2.5-coder:7b",
      sampling: { temperature: 0, seed: 42, numCtx: 8192 },
      raw: { keep_alive: "30m" },
    });
  }
}

Um agente pode sobrescrever chave a chave com @Agent({ sampling }) — útil para deixar parte do fluxo determinística e parte criativa usando o mesmo provider. Para o que o shape neutro não cobre, raw mescla chaves cruas no body.

Custo por tokens

Ollama e OpenAI já têm o usage lido, então tokens aparecem no report sem configuração. Custo exige informar o preço — não há tabela embutida, que envelheceria em silêncio: 

super({ host, model, costPer1kTokens: { input: 0.0005, output: 0.0015 } });

Retry e timeout

Chamadas HTTP falham de formas transitórias — um 429 de rate limit, um 503 momentâneo, a conexão que cai. O retry vem ligado por padrão: sem configurar nada, são 3 tentativas com backoff exponencial. 

super({
  host, model,
  retry: {
    maxAttempts: 3,        // default
    timeoutMs: 120_000,    // sem default — veja abaixo
    initialDelayMs: 500,   // default
    maxDelayMs: 8_000,     // default
    onRetry: (i) => console.warn(`tentativa ${i.attempt} falhou (${i.status})`),
  },
});

super({ host, model, retry: false });   // desliga: uma tentativa só
SituaçãoTenta de novo?
429 rate limit · 408 · 425sim
500 · 502 · 503 · 504sim
erro de rede, conexão caída, abort por timeoutsim
400 · 401 · 403 · 404 e demais 4xxnão — erro de contrato não melhora repetindo

Quando o servidor manda Retry-After, ele vence o backoff calculado. O backoff usa full jitter, para não sincronizar picos entre clientes concorrentes. Para uma decisão própria, passe isRetryable — ele recebe um RetryAttempt ({ attempt, maxAttempts, status?, error?, delayMs }).

Para reaproveitar a mesma política em vários providers, o tipo RetryPolicy é exportado: 

import type { RetryPolicy } from "@thenajs/core";

const resiliente: RetryPolicy = {
  maxAttempts: 5,
  timeoutMs: 120_000,
  onRetry: (i) => logger.warn({ tentativa: i.attempt, status: i.status }),
};

super({ host, model, retry: resiliente });
⚠️ timeoutMs não tem default, de propósito. É o único parâmetro capaz de quebrar um setup que já funcionava — um teto de 120s abortaria um modelo local lento que hoje responde em 200s. Ligue quando quiser que travamento vire falha recuperável: sem ele, uma requisição pendurada só falha no limite do runtime (300s no undici) e derruba a run.
⚠️ Custo. Reexecutar um 5xx pode cobrar duas vezes se o servidor processou a requisição e só a resposta se perdeu. E um 5xx permanente (uma rota que o servidor não suporta) gasta as três tentativas antes de falhar. Em fluxo sensível a custo ou latência, use maxAttempts: 1 ou um isRetryable próprio.
O retry não infla o maxChatCalls de um orçamento de run — as tentativas são uma chamada lógica só. Mas as esperas do backoff contam no maxDurationMs. Quando houve retry, o nó chat do report registra attempts.

Tool calls emitidas como texto

Quando o provider não devolve tool calls nativas, o runtime tenta extrair a chamada do texto da resposta — o caso comum em modelos locais. São reconhecidos <tool_call>…</tool_call>, blocos markdown e os envelopes que os modelos de fato emitem: {name, arguments}, {name, parameters}, {tool, args}, {function:{…}}, argumentos como string JSON.

O nó chat do report registra toolCallSource: "native" | "rescued", então dá para medir o quanto um modelo depende do resgate. rescueToolCalls: false desliga o fallback — o texto vira resposta final, expondo que o modelo não está usando o formato nativo em vez de mascarar.

Baseado em mensagens

O contrato do provider é chat({ tools, messages }), que devolve um turno { assistant, tool? }. As messages seguem papéis (system, user, assistant, tool) — o mesmo formato que Ollama e OpenAI entendem. Se o modelo pedir uma tool, o provider a executa e devolve o turno da tool.

Escrevendo um provider próprio

Qualquer backend vira provider: estenda Providers, chame configure() no construtor e implemente chatInternal. Tudo o que você precisa sai do @thenajs/core — sem dependência extra.

providers/anthropic.provider.ts
import { Providers, pruneUndefined } from "@thenajs/core";
import type {
  ProviderCredentials, RawAssistant, ProviderToolCall,
  ToolType, Message, SamplingParams,
} from "@thenajs/core";

// herda sampling, raw, rescueToolCalls e costPer1kTokens
type Credentials = ProviderCredentials & { apiKey: string; model?: string };

export class AnthropicProvider extends Providers {
  private readonly apiKey: string;
  private readonly model: string;

  constructor(credentials: Credentials) {
    super();
    this.configure(credentials);   // ← os campos comuns, de uma vez
    this.apiKey = credentials.apiKey;
    this.model = credentials.model ?? "claude-sonnet-5";
  }

  protected async chatInternal(
    tools: ToolType[],
    messages: Message[],
    sampling?: SamplingParams,
  ): Promise<RawAssistant> {
    // this.request em vez de fetch: herda retry e timeout de graça
    const { response, attempts } = await this.request("https://api.anthropic.com/v1/messages", {
      method: "POST",
      headers: { "x-api-key": this.apiKey, "content-type": "application/json" },
      body: JSON.stringify({
        model: this.model,
        messages: messages.map(toAnthropic),
        tools: tools.map(toAnthropicTool),
        // pruneUndefined tira as chaves que o usuário não pediu
        ...pruneUndefined({
          temperature: sampling?.temperature,
          top_p: sampling?.topP,
          max_tokens: sampling?.maxTokens ?? 1024,
        }),
        ...this.raw,   // escape hatch, sem cast
      }),
    });

    const data = await response.json();

    const toolCalls: ProviderToolCall[] = data.content
      .filter((b) => b.type === "tool_use")
      .map((b) => ({ id: b.id, name: b.name, arguments: b.input }));

    return {
      content: data.content.find((b) => b.type === "text")?.text ?? "",
      toolCalls: toolCalls.length ? toolCalls : undefined,
      usage: {
        promptTokens: data.usage?.input_tokens,
        completionTokens: data.usage?.output_tokens,
      },
      attempts,   // aparece no report quando houve retry
    };
  }
}

O contrato

chatInternal é o único método obrigatório. Vale saber o que a classe base já faz por você, para não reimplementar:

A base garanteVocê devolve
remover blocos de raciocínio (<think> e afins) do conteúdo content — o texto do modelo, como veio
resgatar a chamada do texto quando não houver toolCalls, e marcar source toolCalls? — só as nativas; não tente resgatar você
validar os argumentos contra o schema da tool e executá-la nada — a execução não é sua
mesclar o sampling do agente sobre o do provider o mapeamento do shape neutro para as chaves da sua API
calcular costUsd a partir de costPer1kTokens usage? — tokens, se a API reportar
retry, backoff e timeout — desde que você use this.request() attempts — repasse o que o request() devolveu

Opcionalmente, sobrescreva embed(input) se o backend tiver embeddings — o default devolve []. E se precisar reaproveitar o parsing de resposta em texto, parser e normalizeToolCallEnvelope também são exportados; para o mapeamento de sampling, pruneUndefined. Quem sobrescreve o chat inteiro (raro) usa o tipo ChatParams.

Embeddings

embed(input) é público: chame direto no provider, sem subclasse intermediária. Para guardar e buscar esses vetores, veja Memória vetorial — ou use o embed() solto, se preferir cuidar do armazenamento você mesmo. 

export class LocalOllamaProvider extends OllamaProvider {
  constructor() {
    super({
      host: "http://localhost:11434",
      model: "qwen2.5-coder:7b",
      embedModel: "nomic-embed-text",   // modelo próprio para embeddings
    });
  }
}

const vetor = await new LocalOllamaProvider().embed("texto");
// → 768 dimensões com o nomic-embed-text
Sem embedModel, o Ollama usa o mesmo model do chat — e a maioria dos modelos de chat não serve para isso. Providers sem suporte a embeddings devolvem [].
Credenciais obrigatórias? O @Agent({ provider }) aceita a classe — e nesse caso a instancia com new Provider(), logo ela precisa de construtor sem argumentos (o padrão de LocalOllamaProvider acima). Se o seu provider exige credenciais, passe uma instância já configurada: @Agent({ provider: new AnthropicProvider({ apiKey }) }).
Nomes: o ProviderToolCall ({ id, name, arguments, source }) é o que você devolve em toolCalls — não confunda com o ToolCall dos hooks, que é { name, args }. O ToolCall exportado pelo @thenajs/agentflow é um alias deprecado do primeiro.
Use um modelo pequeno (ex.: qwen2.5:1.5b) para iterar rápido e um maior (ex.: qwen2.5-coder:7b) quando precisar de qualidade.
