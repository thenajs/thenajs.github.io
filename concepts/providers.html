Providers

O provider é quem conversa com o modelo. O engine traz OllamaProvider e OpenAIProvider; o padrão é criar uma subclasse com as credenciais já configuradas.

providers/ollama.provider.ts
import { OllamaProvider } from "@thenajs/core";

export class LocalOllamaProvider extends OllamaProvider {
  constructor() {
    super({ host: "http://localhost:11434", model: "qwen2.5-coder:7b" });
  }
}

O agente referencia a classe do provider (ou uma instância). Assim as credenciais ficam num lugar só, fora dos agentes.

Parâmetros de amostragem

sampling é um shape neutro que cada provider traduz para as chaves nativas. Nada tem default: o que você não informar não é enviado, e o modelo mantém o comportamento dele. Para iterar determinismo, o par temperature: 0 + seed é o ponto de partida.

providers/ollama.provider.ts
export class LocalOllamaProvider extends OllamaProvider {
  constructor() {
    super({
      host: "http://localhost:11434",
      model: "qwen2.5-coder:7b",
      sampling: { temperature: 0, seed: 42, numCtx: 8192 },
      raw: { keep_alive: "30m" },
    });
  }
}

Um agente pode sobrescrever chave a chave com @Agent({ sampling }) — útil para deixar parte do fluxo determinística e parte criativa usando o mesmo provider. Para o que o shape neutro não cobre, raw mescla chaves cruas no body.

Custo por tokens

Ollama e OpenAI já têm o usage lido, então tokens aparecem no report sem configuração. Custo exige informar o preço — não há tabela embutida, que envelheceria em silêncio: 

super({ host, model, costPer1kTokens: { input: 0.0005, output: 0.0015 } });

Tool calls emitidas como texto

Quando o provider não devolve tool calls nativas, o runtime tenta extrair a chamada do texto da resposta — o caso comum em modelos locais. São reconhecidos <tool_call>…</tool_call>, blocos markdown e os envelopes que os modelos de fato emitem: {name, arguments}, {name, parameters}, {tool, args}, {function:{…}}, argumentos como string JSON.

O nó chat do report registra toolCallSource: "native" | "rescued", então dá para medir o quanto um modelo depende do resgate. rescueToolCalls: false desliga o fallback — o texto vira resposta final, expondo que o modelo não está usando o formato nativo em vez de mascarar.

Baseado em mensagens

O contrato do provider é chat({ tools, messages }), que devolve um turno { assistant, tool? }. As messages seguem papéis (system, user, assistant, tool) — o mesmo formato que Ollama e OpenAI entendem. Se o modelo pedir uma tool, o provider a executa e devolve o turno da tool.

Escrevendo um provider

Qualquer provider estende Providers e implementa o chatInternal(tools, messages, sampling?) (a chamada crua ao modelo). A classe base cuida do resto: extrair a tool call, validar o schema e executar a tool. Para um novo backend, basta traduzir messages para o formato da API, mapear o sampling e devolver o conteúdo — mais o usage, se a API o reportar.

Use um modelo pequeno (ex.: qwen2.5:1.5b) para iterar rápido e um maior (ex.: qwen2.5-coder:7b) quando precisar de qualidade.
