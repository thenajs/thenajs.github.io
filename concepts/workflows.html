Workflows

Um workflow orquestra vários agentes num único pipeline, que compartilha o mesmo estado. Os passos ficam em steps e são combináveis e aninháveis.

Os três tipos de passo

  • agente (a classe) — passo sequencial; a saída de um alimenta o próximo;
  • parallel([...]) — passos concorrentes sobre o mesmo contexto;
  • loop({ steps, until, maxIterations }) — repete até until(ctx) ou o limite.
explorer.workflow.ts
@Workflow({
  steps: [
    PlannerAgent,
    loop({
      maxIterations: 5,
      until: (ctx) => ctx.reviewApproved,
      steps: [ parallel([ExplorerAgent, ReviewerAgent]) ],
    }),
  ],
})
export class ExplorerWorkflow {}

Estado compartilhado

Todos os passos rodam sobre o mesmo estado. Cada agente adiciona seu turno ao history, então o próximo agente já "vê" a conversa até ali. O memory inicial é semeado pelo input/memory do run.

Condição do loop

O until lê o ctx. Para pará-lo por lógica (e não só por maxIterations), um agente precisa gravar o campo lido — por exemplo, um run(input, ctx) que faz ctx.reviewApproved = true. O maxIterations é a rede de segurança.

Parar quando o agente responde

No padrão ReAct (repetir enquanto o agente usa tools, parar quando ele responde sem tool), você não precisa de hook nenhum: o runtime grava um resumo do último turno em ctx.turn, e o until pronto untilAnswered lê isso.

react.workflow.ts
import { Workflow, loop, untilAnswered } from "@thenajs/core";

@Workflow({
  steps: [
    loop({ steps: [ExplorerAgent], until: untilAnswered, maxIterations: 8 }),
  ],
})
export class ReactWorkflow {}

O ExplorerAgent fica limpo (export class ExplorerAgent {}) — sem afterResponse, sem flag. Para condições próprias, leia ctx.turn direto:

  • ctx.turn.calledTool — o turno executou uma tool?
  • ctx.turn.toolName — qual tool o modelo chamou;
  • ctx.turn.response — o texto da resposta final do turno.
untilAnswered é para loops de um agente. Dentro de parallel, vários agentes gravam ctx.turn e a última escrita vence — nesse caso escreva um until próprio.

Paralelo: cuidado com a saída

No parallel, os agentes rodam sobre a mesma entrada e todos escrevem em ctx.output (a última escrita vence). Para ler resultados de agentes paralelos, use o ctx.state (o history acumula os turnos de todos).

Workflows aninhados

Uma tool pode receber o WorkflowRuntime e disparar outro workflow — útil quando uma decisão do agente inicia um processo inteiro (ex.: um deploy).
